## 已解决的时间线问题

- 开场只预告两层问题，不提前解释捕获明光。
- 第50抽三张卡各自标出统计总数，不用同一套颜色暗示互斥分类。
- 未知中段用没有开口大小含义的问号块表示，不画成逐级变宽的官方曲线。
- 五星身份Scene只讲50%基础判定和歪后大保底，55%留到捕获明光Scene。
- 捕获明光Scene把机制画成非保证五星进入身份判定框的一条可能UP路径，不声称先产生非UP结果再改写。
- 结尾把 `0.6% / 1.6% / 90抽` 放在“是否五星”一层，把 `50% / 大保底 / 捕获明光` 放在“是否当期角色”一层。
- 流程箭头采用“状态与规则 → 当前判定 → 结果”，不把问题错误地画成规则的原因。

## 渲染后检查

- `ThreeQuestionsAtFifty`：三张卡的统计总数必须在480p可读。
- `GuaranteeReshapesWaiting`：问号块不能被看成逐级变宽的门。
- `UpIdentityLayer`：保证状态箭头不能与普通分支重叠。
- `CapturingRadiance`：0.018%与55%的统计范围必须同时留在卡片内；三轮时间线不能被读成六个五星全歪。
- `StateMemoryConclusion`：两层规则的空间归属必须清楚。
