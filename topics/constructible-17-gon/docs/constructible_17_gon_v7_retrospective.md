# 正七边形与正十七边形视频 v7 制作复盘

## 最终结果

- 最终高清成片：`topics/constructible-17-gon/exports/final/Constructible17Gon_v7_1080p60_final.mp4`
- 规格：1920×1080、60 fps、13:20.17、H.264 High、48 kHz AAC 单声道、内置中文字幕。
- ChatGPT 标识：位于正片之后的静音片尾，约 7.70 秒。
- 封面：4:3、16:9、3:4 三版，均采用移动端可读的大字标题。
- 验收：全部 24 个场景重新高清渲染；最终成片完整解码无错误；右侧高密度卡片和字幕安全区通过高清关键帧复核。

## 这次反复出现的问题

1. **结论出现了，但观众看不出因果。** 早期版本直接给出“7 不符合、17 符合”，又把 `17-1=16`、奇数因子、候选数量等词放在一起，却没有解释这些量各自在证明中承担什么任务。
2. **从几何到代数的桥缺失。** 直线与圆的交点、四则运算、开平方、最简方程次数都曾以独立知识卡出现，没有先说明当前正在求哪个坐标、为何求交会限制可出现的方程次数。
3. **正确公式缺少可见来路。** `c_k` 与箭头投影、`1+c1+c2+c3=0`、积化和差、下标折回、`A+B=-1`、第二层乘积归类都曾依赖作者脑内的中间步骤。
4. **数学范围没有说完整。** “有三个实数根”和“没有有理根”被说得像互相矛盾；有理根检验的用途、候选来源和一次因式关系也一度先后颠倒。
5. **文案在术语与口语之间失衡。** “可以执行的结构”“运算清单”“给边界一个标签”等自造词既不标准也不自然；数字格式又被机械统一，出现“1 张”之类不符合日常中文的表达。
6. **卡片被当成静态公式墙。** 过程、注释和结论持续向下追加，低清均匀抽帧没有命中短暂的信息峰值，导致右侧卡片的边界风险直到后期才暴露。
7. **总时长正确不等于同步正确。** 多场景单独渲染产生帧级取整误差；只看总时长无法发现关键公式提前出现、末尾靠等待补时或字幕逐渐漂移。
8. **发布层仍有独立风险。** 高清字体度量、libass 字幕缩放、旧高清片段复用、片尾音频长度和封面移动端可读性，都不是低清预览通过后自动成立的。

## 为什么原有规范没有拦住

- **多数规则是建议，不是放行门。** 文档写了“先解释再命名”，但没有要求每个新等式逐项回答动机、来路和用途，因此检查可以形式上通过，观众仍然不知道上一拍怎样走到下一拍。
- **故事状态检查偏重“是否已经出现”。** 它能发现符号抢跑，却不能保证观众理解符号与几何对象的映射，更不能保证推导中的省略步骤对新手可恢复。
- **视觉检查偏重均匀抽帧和最终静帧。** 越界常发生在动画中间的信息峰值；若没有由 Scene 主动声明峰值时刻，固定间隔截图很容易错过。
- **布局约束缺少机器可核对的内部安全框。** 过去主要依靠缩放和肉眼判断，没有把卡片四边、字幕区和子对象包围盒当作硬约束。
- **低清验收与高清发布之间缺少重复视觉门。** 字体、字幕和重新渲染的版本差异可能只在高清阶段出现，旧流程更重视媒体参数，较少要求高清关键帧重审。
- **经验不断按单次反馈追加，缺少分类。** 用词、因果、数学范围、视觉峰值和发布工程混在一起，执行时难以判断某条规则应在哪个阶段由谁检查。

## 已沉淀的硬约束

1. **旁白因果链门。** 每个新符号、等式或判据必须回答：当前在求什么；为什么现在需要它；它怎样由上一拍得到；它让下一步能做什么。缺一项即不进入 TTS。
2. **数学范围标签。** 出现“根、分解、不可约、可解”时必须说明所在范围；例如明确区分实数零点与有理根、有理系数分解与实数分解。
3. **几何—代数同屏映射。** 新符号首次出现时，要让组成它的箭头、投影、点或长度可见，并通过移动、合并或着色动画完成定义，不能只显示公式卡。
4. **卡片状态机。** 每张高密度卡片声明 `进入 → 过程 → 峰值 → 结论替换 → 退出`；放不下时优先替换、淡出或分页，禁止无上限追加。
5. **峰值抽帧门。** 低清检查包含“全片均匀抽帧 + Scene 声明峰值抽帧 + 左右卡片裁切”；高清最终 MP4 必须复查同一批峰值。
6. **卡片安全框。** 在信息峰值检查所有子对象的四边界；字幕安全区不参与卡片可用高度计算，结论条也必须属于某张卡片或明确占用独立区域。
7. **累计帧归一化。** 多场景拼接按累计目标帧取整，每段补帧或裁帧后再拼接，不能独立四舍五入秒数。
8. **高清发布门。** 从当前源码重新渲染、烧录字幕后检查分辨率/帧率/音轨/时长，抽取高清关键帧，并完整解码到结尾；品牌片尾的静音也要实测。

这些规则已分别写入 `docs/workflow.md`、`docs/creative_quality_principles.md` 和 `docs/final_release_checklist.md`，主题级细节继续保留在本文件与 `design_notes.md` 中。
